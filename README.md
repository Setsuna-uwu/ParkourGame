# 雪原跑酷 · 固定雪坡试玩

第一次拉下源码，或改完代码后，双击根目录的 **run.bat** 编译并试玩。编译需要 x64 MinGW-w64（含 gcc 和 g++）或 Visual Studio 的“使用 C++ 的桌面开发”。之后只想玩，直接双击根目录的 **SnowParkour.exe**。程序在本机生成，拉取新代码后再运行一次 run.bat。

角色自动向右滑，橙色的一端是板头。默认显示种子 0 的固定样例坡；按 **F2** 生成下一条随机雪道，按 **R** 在同一条雪道起点重试，按 **Esc** 退出。HUD 左下角会显示当前种子。

复现某条随机路线时，把 `src/main.c` 顶部的 `INITIAL_TERRAIN_SEED` 改成 HUD 上的数字，再运行 `run.bat`。随机地形使用固定种子，绘制和角色查询的是同一份分段数据，不会每帧重新随机。

## 随机雪道（#8 第二阶段）

`src/terrain.c` 把雪道拆成连续分段：平地、缓/陡曲线坡、自然断崖、必须起跳的沟和落坡。种子 0 保留原来的固定样例；其他种子会生成一条可复现的随机路线。普通坡段用 smoothstep 平滑衔接并返回对应的局部坡度，沟和断崖保留硬边；沟后至少留 360 像素恢复跑道。

随机路线会放置金币、备用命和障碍：金币有贴地串和沟上跳跃弧两种，物品编号在同一种子下稳定；`terrain_safe_distance(from)` 会返回当前距离附近、避开障碍的安全雪面。金币现在可以实际拾取，右上角显示本局已收金币数，R/F2 重开时清零。

本地验证：固定样例 + 随机种子自动跑到 12000 像素；沟宽、恢复跑道和安全点均有代码级校验。

## 一局流程（#9）

开局一条正在使用的命，备用命为 0。分数由最远距离、金币和完整后翻组成；只有翻满一圈并站稳的那一帧才加特技分。捡到备用命后摔倒只扣一条，并在 `terrain_safe_distance(from)` 选出的附近安全雪面复活；没有备用命时结算。

按 R/F2 只清本局分数、金币、备用命和已拾取状态，最高分保留。最高分写入运行目录的 `highscore.dat`，关闭再打开仍能读取；文件缺失或损坏时从 0 开始。界面底部显示制作组：Setsuna-uwu（组长）、Wty-Phoenixmoon、shrink ink；真实姓名和学号请在提交前替换 `ROUND_AUTHOR`。

## 同一个断崖的三种试法

- 第一遍松开空格。角色沿缓坡加速，接着滑上一段短上坡，从坡顶自然飞出，落在沟对岸的雪面上。
- 按 R 重试。在板头快到上坡尽头时轻点空格并松开，比第一遍落得更远。
- 再试一次，在同一处起跳。一直按着空格满 160 毫秒，角色就开始后翻；也可以先松手，在空中再按一次，立刻开始翻。松手时雪板会停在当前角度。看橙色板头转完一圈、重新朝右时松手，落稳会显示后翻成功。下次在板头朝左时松手，保持半圈姿势着地就会摔倒。

雪地从距离 300 开始下坡，700 是地面崖沿，750 是对岸。独立木跳台从 560 处接上雪地，向上伸到 680；板头下方还有雪地。水平速度从每帧 4 像素开始，坡度会改变速度，范围为 3 到 8。主动跳比自然离地多给 10 像素/帧的向上速度；重力每帧使向下速度增加 0.5。空中按住每帧后翻 9 度，落地时板面与雪面相差超过 40 度会摔倒。

角色的脚底固定在屏幕横坐标 160。沿雪道每前进多少像素，崖沿就在屏幕上往左移多少。相同位置、相同速度起跳时，轻点和长按的跳跃高度一样；长按只决定何时开始转板。

## 三方公用的约定

- 距离和高度均按像素；世界距离从起点向右增加，屏幕 y 向下增加。角色脚底与地面比较，绘图也从同一处查地面。
- #8 用 `ground_at(distance)` 查雪地，用 `ramp_at(distance)` 独立查木跳台。两者都返回该层是否存在、高度和坡度。板头离地、板下路线和弧形跳台都可以沿用这两个函数。
- #7 的 `player.jump_speed` 是起跳力度，默认 10。需要加强跳时，在起跳前改这个数；`player.jump_height` 则记录本次腾空相对离地点实际升高了多少像素。下次离地时清零。
- #9 在 `LAND_FLIP` 那一帧用 `flip_count(player)` 读完整后翻圈数；在 `LAND_CRASH` 那一帧处理摔倒。有备用命时，由 #9 扣命并调用 `player=start_player(safe_distance)`，位置由 #8 提供，应选没有障碍的实心雪面。此函数只初始化角色。分数、已拾取的物品和生命数归本局保存；若复活点在身后，距离分按本局达到过的最远距离结算，避免同一段反复得分。
- 三人各自从**合入本开工版后的 main** 开任务分支。先交固定坡与事件约定，再并行做完整功能；PR 写明操作、预期结果和实际试玩情况。详细 GitHub 操作见[协作指南](docs/team-workflow.md)。
